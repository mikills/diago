# diago

`diago` runs built-in Go checks, native source analysis, and benchmark-driven pprof reports from one command.


## Installation
```sh
go install github.com/mikills/diago/cmd/diago@latest
diago --version
```

## Suggested workflow for a fresh checkout

Diago names the symbols behind each finding. Fix them, rerun the audit, and repeat. Start with the low-cost, low-risk steps:

```sh
diago format -target .                              # 1. format (mechanical)
diago -target ./...                                 # 2. get go test + go vet green
diago -target ./... -modernize -fix                 # 3. safe auto-fixes (review the diff)
diago -target ./... -deadcode  -fix
diago -target ./...                                 # 4. cleanup loop: fix critical→high→medium, re-run
diago -target ./... -race -coverage -deps -u1000    # 5. tighten with deeper checks
diago -target ./... -format json -output .diago/baseline.json   # 6. snapshot + commit
diago -target ./... -baseline .diago/baseline.json              #    CI gates on NEW findings only
```

Use the performance track only when you have benchmarks. Capture `--perf -format json` before and after a change, then compare the reports with `diago compare`. See [Performance profiling](#performance-profiling) and [Compare perf reports](#compare-perf-reports).

## Usage

### Audit (default)

```sh
diago -target ./...
diago -target ./... -format json -output diago-audit.json
diago -target ./... -race
```
Audit runs Go's test and vet commands, plus native checks for complexity, errors, resource lifecycles, context use, dead-code hints, size, and maintainability.

Native error checks also cover terminal iterator errors. Call `rows.Err()` after iterating `database/sql.Rows` and `scanner.Err()` after a `bufio.Scanner` loop. These report-only rules accept adjacent `//diago:ignore sql-rows-err` or `//diago:ignore scanner-err` directives when the omission is intentional.

JSON audits include the target module's declared Go version and toolchain, the running Go tool version, and rule metadata. `-modernize`, `-u1000`, and `-infertypeargs` record their pinned tool version in check output. They may need Go's automatic toolchain selection or a compatible local toolchain.

#### Generated and ignored files

Generated files are skipped by AST, `-modernize`, `-u1000`, and `-infertypeargs` checks because they must be changed through their generator configuration, not by hand. A file is generated when either condition holds:

- Its name ends in `*.gen.go`, `*.sql.go`, or contains `.generated.`.
- A header comment before `package` contains `DO NOT EDIT`, `Code generated`, or `generated by`.

The header rule covers the canonical Go marker, swaggo headers, and looser variants. Pass `-include-generated` to include these files.

To skip another file, place `//diago:ignore` in its header, above `package`. You can add a reason, for example `//diago:ignore vendored upstream copy`. Ignored files stay skipped even with `-include-generated`.

Suppress an individual finding with a rule-scoped directive on the same or preceding line: `//diago:ignore <rule> <reason>`. The rule name must match exactly; include a reason whenever possible. This works for statement-level rules such as `swallowed-error`, `background-context`, and `ignored-call-result`. A directive for another rule, or one separated by a blank line, has no effect.

Optional checks:
```sh
diago -target ./... -coverage -deps -modernize
diago -target ./... -modernize -fix
diago -target ./... -deadcode
diago -target ./... -deadcode -fix
diago -target ./... -u1000
diago -target ./... -infertypeargs   # report redundant explicit type arguments (gopls, report-only)
```

Formatting with `golines`:
```sh
diago format -target . -max-len 120
# alias: diago fmt
```

Skip native AST checks:
```sh
diago -target ./... -ast=false
```

### Performance profiling

Requires benchmarks.

```sh
diago --perf -target ./... -bench .
diago --perf -target ./pkg -bench BenchmarkHot -format json -output perf.json
```

Perf mode captures CPU, memory, mutex, block, and escape-analysis findings.

Example output:

```txt
top findings:
  - [memory] 14.30% pkg.ParseEscapeOutput at file.go:724
    > findings = append(findings, EscapeFinding{...})
    vars: findings
    calls: append
    allocs: EscapeFinding
    recommendation: inspect detected source signals before changing behavior.

full report: .diago/perf.txt
```

### Compare perf reports

```sh
diago compare before.json after.json
diago compare -format json -output comparison.json before.json after.json
```

## Flags

Audit:

```txt
-target          package path (default ./...)
-output          report path (default .diago/audit.txt)
-format          text or json (default text)
-race            run go test -race
-coverage        collect coverage (default false)
-deps            list dependencies (default false)
-ast             run native AST checks (default true)
-modernize       run gopls modernize diagnostics (default false)
-deadcode        report dead-code hints. With -fix, removes narrow unexported dead functions
-u1000           run Staticcheck U1000 unused-code diagnostics
-infertypeargs   report redundant explicit type arguments via gopls (report-only, no -fix)
-fix             apply fixes for -modernize or -deadcode
-baseline        path to a JSON audit report; report and gate on new findings only
-include-generated  include findings from generated files (skipped by default)
-summary-limit   max critical/high findings in summary. Use -1 for all (default 25)
```

Format:

```txt
-target          source directory to format (default .)
-max-len         maximum line length passed to golines (default 120)
-golines         golines binary to use; falls back to go run github.com/segmentio/golines@latest
```

Perf:

```txt
--perf           enable performance mode
-target          package path (default ./...)
-bench           benchmark regex (default .)
-threshold       minimum cumulative percentage (default 1.0)
-output          report path (default .diago/perf.txt)
-format          text or json (default text)
```

## Skills

Install Diago's bundled agent instructions to tell coding agents how and when to run it. The binary embeds these instructions, so `diago skills` always installs the version that matches your installed Diago.

Claude Code (default) — installs a skill:

```sh
diago skills            # install into ~/.claude/skills (user-level)
diago skills -project   # install into ./.claude/skills (project-local)
```

Other agents, including Codex, Cursor, and Copilot, use the cross-agent `AGENTS.md` convention:

```sh
diago skills -agent agents          # write ./.agents/diago.md + reference block in ./AGENTS.md
diago skills -agent agents -dir DIR # use DIR as the project root
```

The `agents` target writes the full instructions to `.agents/diago.md` and adds a managed `<!-- BEGIN diago -->`…`<!-- END diago -->` block to `AGENTS.md`. Re-running replaces that block and preserves the rest of `AGENTS.md`.

Common flags:

```txt
-agent     target: claude (default) or agents
-project   claude target only: install into ./.claude/skills instead of ~/.claude/skills
-dir       destination base directory (overrides the default location)
-force     overwrite existing files
-list      list bundled skills without installing
```

Restart Claude Code, or your agent, after installation so it loads the new instructions.

## Upgrade

```sh
diago upgrade           # installs latest with go install
diago upgrade v0.1.0    # installs a specific version
```

## Notes

- Reports go to `.diago/` by default. Add `.diago/` to `.gitignore` or set `-output`.
- `go install` writes to `$(go env GOPATH)/bin`; ensure that directory is on `PATH`.
- Audit mode does not require benchmarks.
- Perf mode requires `func BenchmarkX(b *testing.B)` benchmarks.
- Perf mode profiles benchmark runs, not live pprof endpoints. Live pprof endpoint support is not available yet.
